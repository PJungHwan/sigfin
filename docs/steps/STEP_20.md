## 실제 화면 검증

별도 프로필 Edge에서 합성 시연 서버만 연결해 검사했다. 사용자 기존 브라우저/원본 DB에는 접근하지 않았다.

최초 브라우저 검사는 `DATA READY`만 기다리다 실패했다. 새 시연 화면은 합성 기간 제한을 정직하게 **PARTIAL DATA**로 표시하므로 검사 조건을 이에 맞췄다. 앱의 데이터 검증을 비활성화하거나 가짜 정상 상태로 바꾸지 않았다.

후속 두 차례는 입력/버튼 클릭 후 0.7초만 기다린 검사 도구가 전략 등록 갱신 전에 다음 조작을 진행해 비교 실행 조건을 확보하지 못했다. 실제 앱/엔진을 바꾸지 않고 입력 blur와 2초 대기·등록 목록 확인으로 검사 도구를 보완했다. 다음 흐름은 **실제 Edge에서 완료, 미처리 UI 예외 0**이다.

1. 합성 경고/PARTIAL DATA를 확인하고 기존 전략과 이름을 바꾼 전략을 UI로 2개 등록했다. 이름만 다른 동일 조건이므로 전략 성과 차이를 주장하지 않는다.
2. 시험 계좌 생성→BTC/ETH 가격 조회→확인 체크→가상 매수 1건→포트폴리오 위험 분석을 실행했다.
3. Mock 통합 보고서 실행→로컬 저장→과거 조회를 확인했다. 개발자 원본 JSON은 기본 닫힘이며 저장/과거 조회는 기존 구현을 재사용했다.
4. 2전략×Risk×3구간 **12회** 비교→실제 JSON HTTP 다운로드→파일 업로드→저장 입력 재실행→**결과 해시 일치**를 확인했다. 화면 캡처도 확인했다.

보고서 Markdown/JSON·부족/오류 전환·직렬화·원장/백업 복원은 자동 시험 근거와 구분한다. 이번 Edge 흐름에서 손절 1% 체결·실 FRED·유료 LLM·전체 발표 리허설을 검증했다고 주장하지 않는다. 기존 손절/원장/실제 BTC의 사용자 확인은 STEP 18 기록이다. 시연 검사 도구/프로필/다운로드/화면 캡처는 Git 제외 `.pytest_cache`에만 두며 사용자 다운로드 폴더는 읽지 않았다.
