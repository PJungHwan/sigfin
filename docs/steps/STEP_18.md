## 구현 기능

- 사이드바의 기존 전략 작성/JSON 불러오기를 재사용해 이름이 다른 전략 2~6개를 비교 목록에 고정한다. 이후 사이드바 편집은 등록 전략을 소급 변경하지 않는다. 이름만 다르고 조건이 동일한 경우 안내한다.
- 각 전략 × Risk OFF/ON을 독립 실행한다. 2개 전략의 전체 구간은 4조합이고, 시간순 검토/검증도 켜면 총 12회 실행이다. 모든 조합의 초기금·수수료·슬리피지·직전 봉 거래량 참여율은 동일하다.
- 기존 Stop Loss / Take Profit / Trailing Stop 설정을 Risk ON에 적용한다. 모두 OFF라면 두 결과가 같다고 명시한다. ON−OFF 수익률·승률·MDD 차이는 %p, 자산/손익/비용 차이는 USDT다. 위험관리의 성과 우위를 가정하지 않는다.
- 수익률·MDD·종료 거래 기준 승률·최종 자산·평균 종료 손익·총 수수료·실현/미실현 손익·미체결 수와 표본 수를 비교한다. 전략별 색, OFF 점선/ON 실선의 Plotly 자산 곡선을 제공한다.
- 실패 조합은 FAILED/N/A, 일부 성공은 PARTIAL, 모두 실패하면 FAILED다. 무거래의 0 거래/0 수익과 계산 불가 승률/평균 손익을 구분한다. 모든 조건이 유효한 봉이 없으면 INSUFFICIENT_DATA로 안내한다.
- 입력 JSON과 비교 Markdown 다운로드, JSON 업로드 후 **명시적 재실행**을 제공한다. 재실행은 현재 조회/포트폴리오·SQLite·API에 의존하지 않는다. 새 DB 테이블이나 기존 저장 데이터 변경은 없다.

## 고정 입력과 재현성

`ExperimentSnapshot`은 스키마/계산/앱 버전, 계산 소스 SHA-256, 종목·Timeframe·기간·실행 기준 UTC, 원본 OHLCV, 수집 메타데이터·요청 제한 사유, 전략 JSON, 공통 비용/거래량/Risk 설정, 시간순 분할 위치, 입력 SHA-256을 보존한다.

STEP 15의 `pack_frame` / `restore_frame` / `safe_json`을 재사용해 숫자와 UTC dtype을 왕복 보존한다. 스냅샷은 현재 원본 DataFrame과 독립적이다. 초기 구현의 결과 지문 대조는 단위 테스트에서만 수행했고 브라우저는 계산값을 표시했다. 아래 후속 수정에서 저장 기준과 브라우저 자동 비교를 추가했다. 실행 시간/임의 ID는 지문에 넣지 않는다.

8MB 입력, 5,000봉, 전략 6개로 제한한다. 손상 해시·중복 JSON 필드·미지원 스키마·잘못된 종목/봉/시각·비유한 가격/미래 봉을 거부한다. SHA-256은 손상 탐지용이지 원본 인증이나 암호화가 아니다. 계산 소스/버전이 달라진 저장 입력은 같은 버전에서 실행하거나 새 실험을 생성하도록 차단한다.

## 시간순 평가·미래 데이터 방지

- 기본 70% 검토 / 30% 검증이며 10~90%에서 선택한다. 각 구간 최소 2봉이다. 전체 구간 평가와 별개로 각 구간을 동일 초기금·FLAT으로 시작한다. 앞 구간의 포지션/손익/신호 주문을 넘기지 않는다.
- 외부 지표 열을 신뢰하지 않고 **고정 OHLCV만으로 STEP 3의 인과적 지표 함수를 재계산**한다. 검증 구간 지표는 앞선 검토 구간을 워밍업으로 사용할 수 있다. 미래 검증 값을 수정해도 검토 구간 결과가 달라지지 않는지 시험한다.
- 화면용 시장 서비스가 제거한 구간 이전 OHLCV는 추가 수집하지 않는다. 따라서 전체/검토 시작에는 외부 워밍업이 없고 초기 NaN을 유지한다. 기존 단일 백테스트의 외부 워밍업으로 계산된 값과 초기 신호가 다를 수 있음을 안내한다.
- 검증 첫 봉 Cross는 구간 내 직전 행이 없어 False다. 첫 봉에서 확인된 일반 조건도 두 번째 연속 봉 시가부터 체결한다. 마지막 신호에는 다음 봉이 없어 체결하지 않는다. 첫 봉 진입을 만들기 위해 앞 구간 신호를 가져오지 않는다.
- 간격 누락 시 지표를 재초기화하고 주문을 뒤 봉으로 건너뛰어 체결하지 않는다. Risk 봉 내부 우선순위·직전 봉까지의 trailing 극값·미체결 재시도는 기존 STEP 6을 그대로 사용한다.
- 현재 가상 계좌·FRED 개정값·LLM 판단은 이 백테스트 입력에 포함하지 않는다. 검증 결과를 본 뒤 전략을 수정해 같은 구간을 다시 평가하는 것을 독립 검증이라고 부르지 않는다. 자동 최적화/통계적 유의성·예측 확률 기능은 없다.

## 결과 해시 자동 비교 보완 — 2026-11-11

### 확인된 원인

사용자가 실제 브라우저에서 저장 입력으로 12회 재실행하고 주요 성과가 일치함을 확인했다. 그러나 초기 `result_digest()`는 해시를 계산할 뿐, UI의 재실행 처리에서는 원본 결과와 비교하지 않았다. 기존 JSON에는 입력 스냅샷만 있고 결과 기준 해시는 없었다. 이전 화면의 **실험 조건·전략·한계**와 Markdown의 **결과 SHA-256**은 계산값 표시였으며, 자동 일치 확인은 아니었다. 사용자의 실제 파일/해시 일치 여부를 이 기록에서 추정하지 않는다.

### 수정과 호환성

- 신규 [backtest/experiment_verification.py](../../backtest/experiment_verification.py)에 결과 기준·비교·저장 파일 어댑터를 추가했다. 기존 `backtest/experiments.py`, 입력 스키마/해시, 계산 소스 목록, 환경 설정은 이번 수정에서 변경하지 않았다. 따라서 기존 JSON의 계산 코드 해시를 UI 보완 때문에 무효화하지 않는다.
- 새 다운로드 JSON은 `artifact_schema_version: 1`, 기존 원본 `snapshot`, `reference`를 가진다. reference에는 입력 해시, 결과 해시, 결과 해시 알고리즘, 원본 실행 상태를 저장한다. 기존 입력 JSON도 계속 읽을 수 있다. 기존 파일/SQLite는 수정하지 않는다.
- 새 파일은 원본 세션 없이도 저장 기준을 사용한다. 기존 JSON은 같은 **입력 SHA-256**의 현재 세션 원본 실행이 있을 때만 그것을 기준으로 삼고, 없으면 비교 불가다. 단지 가격/성과가 비슷하다는 이유로 다른 실험과 비교하지 않는다.
- 기준/재실행 중 PARTIAL/FAILED, 서로 다른 입력 또는 알고리즘, 기준 없음은 **비교 불가**다. 동일 조건의 완전 성공 결과끼리 SHA-256이 같으면 **일치**, 다르면 **불일치**다. 불일치는 백테스트 실행 실패와 별개로 표시한다.
- 재실행 결과를 다시 다운로드할 때 기존 기준이 있으면 그대로 유지한다. 불일치를 새 기준으로 자동 교체해 숨기지 않는다. 기존 JSON에 기준이 없다면 새 다운로드는 **이번 재실행**을 향후 비교 기준으로 저장하며 과거 원본 일치를 소급 증명하지 않는다.
- 업로드 파일이 변경/제거되면 이전 재실행/해시 상태를 무효화한다. 표시 토글/일반 rerun은 비교 결과와 다운로드를 유지한다. 페이지 표시만으로 엔진/API를 다시 호출하지 않는다.

### 비교 대상과 확인 위치

**저장 실험 재현 → 저장 입력으로 재실행** 후 결과 바로 위에 상태가 표시된다. **결과 해시 비교 기준**을 펼치면 기준 출처, 기준/재실행 SHA-256, 입력 SHA-256, 알고리즘을 볼 수 있다. 화면에서 고른 구간의 4개만이 아니라 **전체·검토·검증의 모든 조합(해당 설정에서는 12개)**을 비교한다.

기존 `result_digest()` 그대로 성과 지표·최종 포지션·자산 곡선·거래·체결 이벤트·오류를 정규화하고, 구간/전략명/Risk로 조합을 정렬한 뒤 SHA-256을 계산한다. 표는 pandas `orient="split"`, 날짜는 ISO UTC ns, 부동소수점은 `double_precision=15`다. 임의 실행 ID/실행 소요시간은 제외한다. 지표 시계열 전체나 신호 마스크 자체를 별도로 해시하지는 않는다. 입력 해시 검증과 결과 해시 비교는 별개이며 저장 기준은 전자서명/원본 인증이 아니다.

브라우저에서는 새로 다운로드한 JSON을 업로드해 재실행하고 일치 상태와 양쪽 해시를 확인한다. 기존 JSON은 같은 입력 원본이 세션에 없으면 비교 불가가 정상이다. 이 경우 이전 Markdown의 `결과 SHA-256`과 새 화면의 재실행 해시를 수동으로 대조할 수 있지만, 기준이 없는 기존 JSON만으로 자동 일치를 주장하지 않는다.

## Risk ON/OFF 최종 검증 — 2026-11-11

### 원인과 설정 전달 경로

사용자가 확인한 `stop_loss_enabled / take_profit_enabled / trailing_stop_enabled = false`는 세 규칙이 모두 비활성화된 설정이다. 비율 0.03/0.06/0.03만 저장돼 있어도 활성화 플래그가 false이면 적용하지 않는다. 따라서 **Risk ON/OFF 성과 차이 0과 모두 비활성화 안내는 정상 동작**이다. Risk ON이라는 조합 이름 자체가 규칙을 강제로 켜지지는 않는다.

설정 UI는 이미 존재한다. 이번 검증에서는 앱·UI·엔진·설정 코드를 수정하거나 중복 UI를 추가하지 않았다.

```text
ui/backtest_view.py: render_backtest_controls()
  → render_risk_controls(): 체크박스 + % 입력 / 100 → RiskConfig
app.py: backtest_settings, risk_settings 수신
  → render_experiments(..., backtest_settings, risk_settings, ...)
ui/experiment_view.py: capture_experiment(..., settings, risk, ...)
backtest/experiments.py: snapshot.risk에 고정 → execute_experiment()
  → OFF: 기본 RiskConfig() (모두 비활성화)
  → ON: 저장된 RiskConfig(**snapshot.risk)
  → 동일 OHLCV·초기금·비용·거래량 참여율로 각각 run_backtest()
```

### 실제 화면에서 활성화하는 방법

1. STEP 18 비교 영역보다 위쪽의 **백테스팅** 영역을 찾는다. **Risk Management · 손절·익절·트레일링** 접기 메뉴를 연다.
2. **Stop Loss 활성화**를 체크한다. 활성화된 **Stop Loss 비율 (%)**에 **1.0**을 입력한다. UI는 % 단위이고 저장 값은 `0.01`이다. 필요하면 Take Profit/Trailing Stop도 각각 체크·입력한다. 규칙별 활성화는 독립적이다.
3. 아래 **백테스트 전략 비교 · 고정 실험 → 비교 전략 등록·실험 설정 → 전략 × Risk 비교 실행**을 누른다. 위쪽 단일 **백테스팅 실행**이나 **Risk ON/OFF 비교 실행** 버튼을 먼저 누를 필요는 없다.
4. **실험 조건·전략·한계 → Risk ON 설정**에서 `stop_loss_enabled: true`, `stop_loss_rate: 0.01`을 확인한다. 변경 후 기존 현재 결과는 무효화되므로 새로 실행해야 한다.
5. **조합별 거래·체결 원장**을 열고 선택한 구간의 **Risk ON** 표에서 `action=EXIT`, `status=FILLED`, `exit_reason=STOP_LOSS`, `price`, `execution_timing`, 발생 봉을 확인한다. 열이 많으면 표를 가로로 이동한다. 거래표에도 `exit_reason`이 있다. 미체결은 `status=REJECTED`와 거절 사유/거래량 한도를 확인한다.
6. 새 실험 JSON을 다운로드하고 업로드해 재실행하면 활성화된 손절 설정과 결과 해시를 그대로 재현한다. **기존 OFF JSON 재실행은 그 파일의 false 설정을 유지**한다. 현재 UI를 켜도 저장 파일의 실험 조건을 덮어쓰지 않으므로 새 설정 검증에는 먼저 새 비교 실험을 생성해야 한다.

활성화해도 실제 보유 포지션이 없거나 보호 가격에 닿지 않으면 차이는 0일 수 있다. 다른 신호가 먼저 청산하거나 유동성 부족으로 손절 체결이 거절될 수도 있다. 차이를 만들기 위해 가격/신호/체결을 임의 조작하지 않는다.

### 손계산 가능한 합성 검증

검토/검증에 각각 확정 봉 4개, 총 8개를 사용했다. 종가는 `100, 102, 103, 104`가 두 번 반복되고 각 구간의 두 번째 봉 시가는 100, 저가는 98.5다. 종가가 101 미만(전략 A) 또는 100.5 미만(전략 B)일 때 LONG 신호가 발생하고 다음 연속 봉 시가 100에 진입한다. 두 전략은 이 합성 구간에서 같은 신호를 만들지만 조건값은 다르다. 손절 1%는 진입가 100의 99이며 진입 봉에서 접촉한다.

초기금 1,000, 비용 0, 충분한 직전 거래량 조건의 결과다. **실제 시장 성과가 아니다.**

| 구간 (전략 A/B 각각) | Risk OFF 최종 자산 | 손절 1% ON 최종 자산 | ON − OFF |
| --- | --- | --- | --- |
| 전체 | 1,040 | 980.1 | −59.9 USDT |
| 검토 (독립 FLAT) | 1,040 | 990 | −50 USDT |
| 검증 (독립 FLAT) | 1,040 | 990 | −50 USDT |

전체 ON에서는 두 번의 손절로 `1,000 × 0.99 × 0.99 = 980.1`이다. OFF는 한 포지션을 마지막 종가 104로 평가한다. ON의 손절은 모두 `STOP_LOSS / FILLED / INTRABAR_OHLC / price=99`로 기록됐다. 수익 개선을 가정하지 않는 예제다.

편도 수수료 0.1%·슬리피지 0.05%도 별도 검산했다. 진입가 `100×1.0005`, 수량 `1000/(진입가×1.001)`, 손절 매도가 `진입가×0.99×0.9995`, 최종 현금 `수량×손절 매도가×0.999` 및 왕복 수수료 합계를 기존 엔진 결과와 대조했다.

### 체결 규약과 미래 데이터

전략 진입/신호 청산은 기존의 **다음 연속 봉 시가** 규칙을 유지한다. 손절 등 리스크 청산을 다음 시가로 미루는 변경은 하지 않았다. 시가 갭/봉 내부 OHLC 접촉/미체결 시가 재시도는 [STEP 6 체결 계약](../risk_management.md)을 따른다. 진입 봉 리스크도 적용하며 봉 내부 정확한 체결 시각은 NaT로 두고 발생 봉만 기록한다. 현재 봉 극값의 trailing 소급 적용과 미래 봉 거래량 사용을 금지하는 기존 테스트를 함께 실행한다.

신규 검증은 전체·검토·검증의 12개 조합, Risk OFF 비활성화·ON 1%, next-open 진입/STOP_LOSS 원장, 비용/회계, 미래 검증 구간 변경 시 검토 결과 불변, JSON/기준 결과 해시 일치, 기존 화면 활성화·1.0 입력·설정 변경 무효화·다시 OFF 동일성·캐시 조회 1회를 확인한다.
