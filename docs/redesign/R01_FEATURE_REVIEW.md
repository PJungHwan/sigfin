# R01 — 기능 정리 후보와 변경 영향

기준: **`4266787` / 2026-11-12**. [R01 기준선](R01_BASELINE.md)·[리디자인 계획](../UI_UX_REDESIGN_PLAN.md)과 함께 본다.

**이 문서는 제안이다. 실제 기능 이동/숨김/삭제는 없다. 핵심 분석·계산·저장 기능의 삭제 권고는 0개다.** 같은 데이터를 사용한다는 이유만으로 기능이나 저장 형식이 같다고 판단하지 않는다.

## 1. 분류 기준

- **A 유지:** 사용자가 결과/안전성을 판단하거나 기존 작업을 수행하는 데 필요한 기능.
- **B 다른 화면과 통합:** 탐색/설정/표시 공간을 함께 구성한다. 엔진·스키마·실행 트리거를 합치거나 한 기능으로 대체한다는 뜻이 아니다.
- **C 고급/개발자 메뉴:** 상세 설명/진단만 접고 진입 경로를 유지한다. 핵심 상태·실패·비용·안전 안내는 계속 보이게 한다.
- **D 삭제 검토:** 기능이 아닌 중복/개발 단계 표시의 표현 후보만 검토한다. 확정/자동 삭제 승인이 아니다.

아래 위험도는 **UI 변경/제거에 따른 회귀 위험**이며 시장의 투자 위험 등급과 다르다. A/B/C는 추천 주처리이며 같은 기능의 상세 설명은 C로 접을 수 있다.

## 4. 중점 검토 결론

### 단일 AI / Workflow / 통합 보고

**화면은 B, 기능은 유지.** 단일 분석은 단일 응답 계약, Workflow는 역할별 노드 실행/옵션, 통합 보고는 검증된 결과와 계산/원장 자료의 출처 연결이다. 화면/기본 읽기 순서는 통합 보고 중심으로 정리할 수 있지만 세 실행의 승인·mode·입력 지문·결과 ID를 하나로 합치지 않는다.

통합 Mock는 직접 기존 그래프의 Debate/Risk를 실행한다. 선택 Live 보고서의 Debate/Risk 보충은 동일 문맥의 별도 Mock 실행으로 출처를 구분하며, 자동 유료 Debate/Risk를 실행하지 않는다. Workflow를 삭제하면 세부 그래프/ON-OFF/라운드 선택과 보충 실행 경로가 줄어들 수 있다.

### 단일 백테스트 / 복수 비교

**같은 전략 작업 화면으로 B, 두 기능 유지.** 현재 편집 전략을 1회 검산하는 작업과 등록 전략 2~6개×Risk×구간을 고정 실행하는 실험은 다르다. 공통 비용/Risk 원본을 가까이 두고 표/원장/차트 컴포넌트를 공유하되, 최소 전략 수·구간 초기화·업로드 독립성·결과 SHA 계약을 유지한다.

### 중복처럼 보이는 Risk 설정

**시각 패턴/원본 위치만 정리.** 백테스트 손익절·AI Risk 가상 노출·보유 계좌 충격은 세 가지 의미다. 자동으로 한 값을 세 군데 전파하면 레버리지/위험 한도·가정 가격과 실제 보유량을 혼동한다. 이미 있는 명시적 ‘백테스트 설정 가져오기’는 유지하고 적용 대상을 보여준다.

### 원본 JSON / 상세 로그 / 저장 이력

**JSON·상세 진단은 C, 근거·저장 기능은 A/B.** 개발자 JSON은 이미 기본 닫힘이므로 새로 해결해야 할 오류로 재등록하지 않는다. 오류 유형·PARTIAL/FAILED·핵심 경고는 기본 화면에서 볼 수 있어야 한다. 이력 화면은 종류/ID·현재/과거·원장/보고서/실험 파일의 목적을 구분해 통합하고 저장 데이터를 삭제하지 않는다.
