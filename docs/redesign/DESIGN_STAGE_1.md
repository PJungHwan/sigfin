기록일: **2026-11-12 (Asia/Seoul)** · 기능 기준 `4266787` · R01 기준선 커밋 **`ccf8d63`**

**1단계 설계 완료 / 후속 2단계 전체 UI 구현 완료 / 3단계 최종 검증·보완 미착수.** 이 문서는 설계 기록이며, 후속 [2단계 구현·실제 검증 범위](IMPLEMENTATION_STAGE_2.md)를 별도로 확인한다. 전체 사용성/접근성·사용자 수용이 완료됐다는 뜻은 아니다.

## 1. 확정 디자인 콘셉트

**‘차트와 검증 근거를 빠르게 읽는 한국어 금융 연구 작업 공간’**으로 설계한다.

- 브랜드는 **SIGFIN · 시그핀**이다. 제품명은 좌측 메뉴 상단에 한 번 표시하고, 본문 상단에는 현재 작업 이름을 표시한다.
- 토스증권에서 원하는 간결한 정보 위계는 **핵심 값 → 결과 요약 → 근거/상세** 순서로 적용한다. TradingView에서 원하는 작업 공간은 **넓은 차트와 가까운 조건 제어**로 반영한다. 기존 Plotly를 유지한다.
- 화면의 주요 행동은 조회·검증·분석·가상 기록이다. 새 주문/자동매매·확률 예측·차트 도형 도구·외부 차트 라이브러리를 추가하지 않는다.
- 긴 단일 페이지를 6개 목적 화면과 필요한 하위 탭으로 나눈다. 기본 화면은 시장 분석이며 별도 종합 홈을 신설하지 않는다.
- 핵심 숫자·명확한 단위·상태를 우선하고, 큰 장식/반복 제목/설명 카드를 줄인다. 자료 부족과 실패·비용 경고는 계속 보인다.
- 한국어 표시를 통일하되 저장 JSON·enum·수치 컬럼·실행 ID·버전/해시의 원본 값은 유지한다.

│                    │ [근거·원장·설정·고급 정보는 하위 탭/접기]              │

### 좌측 메뉴

- 메뉴명과 순서는 **시장 분석 → 전략·백테스트 → 포트폴리오 → 거시경제 → AI 연구 → 저장 이력**으로 고정한다.
- 기존 Streamlit의 `st.navigation(position="sidebar")`와 화면 어댑터를 사용한다. 본문에 같은 메뉴를 다시 만들지 않는다.
- 좌측은 탐색용이다. 전략 편집·거시 체크박스·AI 실행 버튼을 모두 좌측에 누적하지 않고 각 작업 화면으로 옮긴다.
- 데스크톱 메뉴 폭은 약 240~260px를 목표로 네이티브 레이아웃에 맞춘다. 좁은 화면에서는 접을 수 있어야 한다. 합성 자료/실제 주문 없음 안내는 메뉴를 접어도 본문에서 확인 가능하게 한다.

### 상단 정보 영역

- 종목/봉/현재 조회 기간 위젯은 진입점 공통 영역에서 **한 번만** 렌더링하고 기존 키/현재 선택을 유지한다. 본문 설정에 같은 위젯을 중복 생성하지 않는다.
- 시장 자료를 쓰는 화면은 확정 봉 시각·수집 시각·실제 수집 구간/제한을 확인할 수 있게 한다. 조회되지 않았으면 미조회/N/A로 표시한다.
- 전역 조건을 보여주는 것만으로 이력 화면에서 시장/API를 재조회하지 않는다. 과거 보고서·업로드 실험의 조건은 현재 조회 조건과 별도 배너에 표시한다.
- 자료 출처(공개 자료/합성/업로드 입력), 분석 방식(Mock/LLM 선택·실제 호출 여부), 결과 범위(현재/과거)를 분리한다. 업로드된 파일의 출처 주장을 인증된 실 데이터로 표시하지 않는다.

### 읽기·스크롤 정책

- 첫 화면에는 핵심 값과 현재 목적의 주 콘텐츠를 배치한다. 모든 로그·원장을 한꺼번에 세로로 펼치지 않는다.
- 큰 차트·긴 표 자체에는 필요한 공간을 주되, 결과 종류는 하위 탭으로 선택한다. ‘스크롤 최소화’를 모든 자료가 한 화면에 들어간다는 보장으로 표현하지 않는다.
- 1366×768 이상에서 주 작업을 우선하고 768px/390px 및 확대 시 다열 카드·설정을 세로로 전환한다. 페이지 전체의 강제 가로 스크롤을 피한다.
- 탭/접기 안의 비활성 내용도 계산될 수 있으므로, 화면 실행을 명시적으로 제어한다. 접기 상태를 API/거래/저장 차단 장치로 사용하지 않는다.

## 3. 6개 핵심 화면의 확정 배치

### 3.1 시장 분석 — 기본 진입 화면

**상단:** 최신 확정 종가·해당 봉 변화율·RSI(14)·MACD Histogram의 4개 카드. 확정 마감/수집 UTC와 부족/부분 자료 상태를 함께 표시한다.

**본문:** 넓은 캔들/거래량 차트를 중심으로 배치하고 지표 토글·전략 신호/가상 체결 표시를 가까이 둔다. EMA/SMA/Bollinger는 오버레이, RSI/MACD는 기존 공유 시간축 보조 패널을 유지한다. 넓은 화면의 보조 열에는 현재 선택 지표의 기존 상태·자료 품질·범례를 간결하게 놓고 좁으면 아래로 이동한다.

**하단/고급:** 실제 수집 구간/지표 부족 이유·오류 진단·신호 상세. 핵심 오류는 기본 화면에도 남긴다. 분석 요약을 위해 새 LLM을 호출하거나 임의 해석 수치를 만들지 않는다. 단일 AI SIGNAL은 AI 연구로 옮겨 출처를 명확히 한다.

### 3.2 전략·백테스트 — 하나의 전략 작업 공간

**상단:** 현재 편집 전략 이름/조건 요약, 공통 원금·수수료·슬리피지·거래량 참여율·활성 손익절 요약. 공통 설정 원본은 하나이며 설정을 바로 열 수 있어야 한다.

**하위 작업:** `전략 편집 / 단일 백테스트 / 전략 비교 / 저장 실험 재현`으로 나눈다.

- 편집: LONG/SHORT 조건, 행 추가/삭제, 같은 방향 AND/OR, 숫자/지표 비교, 전략 JSON 저장/불러오기. 넓으면 양측 병렬, 좁으면 세로로 배치한다.
- 단일 백테스트: 현재 전략 1개 검산·Risk ON/OFF·성과/곡선/원장. 복수 비교의 최소 전략 수 제한으로 대체하지 않는다.
- 전략 비교: 2~6개 고정 전략 등록, 전체/검토/검증 구간, 동일 비용/Risk 요약, 실행 버튼. 모든 Risk가 OFF면 기존 안내를 노출한다.
- 저장 실험 재현: 현재 조회와 독립된 업로드 입력·명시적 재실행·기준/재실행 해시. 결과 근처에 일치/불일치/비교 불가를 표시한다.

**결과 내부:** 성과/곡선 → 거래·체결 원장 → 실험 조건·재현 상세. 손절 1% 입력은 기존대로 0.01로 전달한다. 업로드 설정을 현재 UI 값으로 바꾸거나 기준 SHA를 갱신하지 않는다.

### 3.3 포트폴리오 — 가상 계좌와 실제 보유 위험

**상단:** 현금·총자산·실현/미실현 손익과 계좌/평가 시각. 평가 불가이면 현금/원장은 보존하고 총자산/비중은 N/A로 구분한다.

**하위 작업:** `보유·가상 기록 / 위험 분석 / 거래·평가 이력`이다.

- 보유·가상 기록: BTC/ETH 보유 표·평균 매입가·비용·평가액. 가격 조회와 수동 BUY/SELL 확인 폼을 배치한다. 새 계좌/초기화는 구분된 보조 동작과 기존 확인 절차를 유지한다.
- 위험 분석: 비중/집중·하락 충격·허용 손실·계좌 이력 MDD/변동성·별도 단일 자산 Risk 결과. 공통 가격 문맥을 재검증한다.
- 거래·평가 이력: 계좌 이벤트/관측값·현재 평가 저장과 원장 JSON 내보내기. 전체 저장 계좌 탐색은 저장 이력 메뉴로 연결한다.

무레버리지·양수 보유 원장을 유지한다. RM의 가상 레버리지를 이 계좌의 실제 노출 설정으로 적용하지 않는다. 위험 탭만 열어도 정상 가격/계좌 문맥을 얻되, 없을 때 N/A 안전장치를 우회하지 않는다.

### 3.4 거시경제 — 원본과 사후 탐색 구분

**하위 작업:** `경제지표 조회 / 암호화폐·거시경제 관계`다.

- 원본: CPI/FEDFUNDS/UNRATE/PAYEMS/DGS10 선택·기간·명시적 조회, 최신 관측값/관측일·단위/주기와 지표별 차트. CPI 지수와 YoY를 구분한다.
- 관계 탐색: 기존 변환·월별 집계·Pearson/Spearman·0~3개월 lag·실제 표본/기간·정규화 추이·산점도/시차 차트.

서로 다른 단위를 같은 가격축에 섞지 않는다. `%`와 `%p`, 고용 ‘천 명’을 유지하고 발표일/빈티지 미확인·사후 관계/소표본 한계를 요약 근처에 둔다. 선택된 Macro 자료는 기존 순서/검증을 유지해 AI 연구로 전달하며 새 관측일 기반 forward-fill을 만들지 않는다.

### 3.5 AI 연구 — 통합 리포트 중심, 세 경로 보존

**하위 작업:** 기본 `통합 리포트`, 별도 `에이전트 워크플로우`, `단일 AI 분석(고급)`이다. 단일 분석은 숨겨 없애지 않고 명확한 진입점을 둔다.

**공통 읽기 순서:** 자료/실행 모드·실제 호출 여부 → 분석 의견과 별도 위험/연구 상태 → 기술/Macro 요약 → 상승/하락·상충/위험·자료 부족 → 검증 근거 → 저장/다운로드·고급 실행 정보.

- 세 경로의 mode·요청/결과 스키마·승인 서명은 분리하고 `_ai_ledger`만 기존대로 공유한다. 기본은 Mock다.
- LLM 경로에는 모델/키 설정 여부·가격 유효성·예상 비용·한도·해당 요청 비용 승인·명시적 실행 버튼을 함께 배치한다. 키나 인증 헤더는 표시하지 않는다.
- Workflow의 Debate/Risk ON/OFF·라운드/가상 위험 설정을 유지한다. 통합 Mock가 기존 규칙으로 Debate/Risk를 실행하는 것과 같은 스위치인 것처럼 합치지 않는다.
- 방향과 위험은 다른 카드/문구로 표현한다. BULLISH/HIGH/ABSTAIN이 함께 나와도 상충처럼 숨기거나 하나로 강제 합치지 않는다.
- 필수 오류/부분 실패/자료 부족은 기본 화면에, 전체 노드 로그·그래프·라운드 상세·원본 JSON은 고급 메뉴에 둔다. JSON 기본 닫힘/재조회 초기화와 공개 근거 접근을 유지한다.
- 저장 버튼/Markdown/JSON은 해당 실행 결과 가까이에 둔다. 과거 저장 조회는 저장 이력으로 연결하며 새 호출을 하지 않는다.

### 3.6 저장 이력 — 과거 자료의 조회·명시적 복원

**상단:** `연구 결과 / 가상 계좌·평가 이력`을 선택하고 기존 ID/자료 종류/저장 시각을 확인한다. 원 Workflow 스냅샷과 통합 보고서의 payload 차이를 보존한다.

**본문:** 과거 선택 목록과 읽기 쉬운 요약·근거·위험/한계, 명시적 계좌 복원/원장 JSON 검증·내보내기. `과거 저장 결과` 배너와 당시 조건을 표시한다. 원본 데이터는 기본 닫힌 개발자 메뉴에서만 제공한다.

현재 Workflow/통합 보고서 저장은 각 현재 분석 화면의 명시 동작으로 유지한다. 과거 조회가 현재 원장을 교체하거나 현재 결과를 덮어쓰지 않는다. 실험 JSON은 전략 화면의 재현 경로로 연결하며 실험용 SQLite 테이블을 신설하지 않는다. 현재 200개 분석 목록 등 기존 조회 한도와 파일 제한을 유지한다.

### 변경 불가 계약

- 전략 초안/동적 행·등록 전략·백테스트 비용/Risk·계좌/nonce/revision·거시 선택·업로드 기준·미저장 메모·공유 예산을 페이지 이동에서 보존한다. 버튼/폼 이벤트는 재실행하지 않는다.
- 가격은 `PortfolioPriceContext` 객체와 검증된 UTC/계좌 revision을 전달한다. 같은 이름의 세션 튜플을 대신 쓰지 않는다.
- 백테스트/Workflow/통합 리포트/실험의 서로 다른 무효화 규칙을 유지한다. 수집 시각만 바뀌는 저장 오류와 실제 입력 변경 무효화를 구분한다.
- 계산 파일 11개·백엔드 소스 78개·STEP 18 입력/결과 SHA·next-open·비용/거래량/손익절 규칙을 유지한다. 통과를 위해 R01 manifest/기준 SHA를 바꾸지 않는다.
- SQLite v1·원본 데이터/이벤트·ID/revision·JSON/Markdown payload·파일명/mime·정밀도·기존 한도를 유지한다. 새 테마/페이지 정보를 저장 모델에 넣지 않는다.
- 유료 요청은 명시적 경로 선택/키·유효 가격/해당 비용 승인/한도와 기존 재시도·동시성 예약·중복 차단을 유지한다. 실제 호출 없는 결과를 Live 응답으로 표시하지 않는다.
- 일반 앱과 오프라인 합성 진입점을 모두 유지한다. 합성 시연의 HTTP/SDK 차단·UUID 시험 DB·잠금·전 화면 배너를 보존한다.
