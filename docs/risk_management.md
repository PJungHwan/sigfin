# STEP 6 리스크 관리 백테스트

`run_backtest(data, strategy, settings, risk=RiskConfig(...))`는 Streamlit 없이 실행한다.
기본 `RiskConfig()`는 모두 OFF다. `compare_risk(...)`는 동일한 데이터·전략·초기금·비용·
거래량 참여율·확정 여부 기준 시각으로 OFF/ON을 독립 실행한다. 어느 한쪽 계산이 실패하면
성공한 쪽만 비교 결과처럼 반환하지 않는다.

## 기준 가격과 설정

비율은 소수 단위다(0.03 = 3%). 활성화 플래그는 bool, 비율은 유한한 0 초과 1 미만만
허용한다. SHORT 목표가가 0 이하가 되지 않도록 익절도 같은 범위로 제한한다.
비활성 비율은 체결 계산 및 UI 결과 식별에 사용하지 않는다.

진입가 `P`는 **진입 슬리피지가 반영된 가상 체결가**다. 수수료는 별도로 지급한다.
`H*`, `L*`는 직전 봉까지 확인한 유리한 극값이며 진입 직후에는 `P`로 초기화한다.

| 기능 | LONG 기준가 | SHORT 기준가 |
| --- | --- | --- |
| Stop Loss | P × (1 − 손절률) | P × (1 + 손절률) |
| Take Profit | P × (1 + 익절률) | P × (1 − 익절률) |
| Trailing Stop | H* × (1 − 트레일링률) | L* × (1 + 트레일링률) |

현재 봉 청산 판단 **이후** LONG은 `max(H*, high)`, SHORT는 `min(L*, low)`로 갱신하고
다음 봉에서만 사용한다. 현재 봉 극값을 같은 봉 트레일링에 소급 적용하지 않는다.
이 비율은 수수료 차감 후 수익률을 보장하는 값이 아니다.

## 봉별 처리 순서와 모호한 체결

1. 이전 리스크 청산이 거래량 부족으로 거절됐다면 다음 **관측 봉 시가**에 재시도한다.
2. 기존 포지션의 시가가 리스크 기준을 넘었거나 같으면 원시 시가로 청산한다.
   시가에서 이미 익절했으면 이후 저가가 손절 기준에 닿아도 시가 익절이 우선한다.
3. 리스크 시도가 없으면 직전 확정 신호를 다음 **연속 봉 시가**에 처리한다.
   반대 신호 청산은 이후 봉 내부 리스크보다 우선한다. 시가 리스크 시도가 있었다면
   미체결 여부와 관계없이 해당 시가의 신호 주문은 취소한다.
4. 포지션이 남고 해당 봉에서 리스크를 아직 시도하지 않았다면 OHLC 범위 접촉을 판단한다.
5. 유리한 극값을 다음 봉용으로 갱신하고 현재 확정 종가로 자산을 평가한다.

LONG은 low가 보호선 이하, high가 목표 이상이면 접촉이고 SHORT는 반대다. 경계값이
같아도 접촉이다. 봉 내부 손절/트레일링과 익절이 함께 접촉하면 보호선을 우선한다.
일반 손절과 트레일링이 함께 접촉하면 LONG은 **더 낮은** 기준가, SHORT는 **더 높은**
기준가를 선택한다. 동일 기준가 동률은 일반 손절이다. `risk_candidates`에 함께 닿은
기준을 모두 기록한다. 실제 고가/저가 발생 순서를 알아낸 결과가 아닌 보수적인 가정이다.

**진입 봉도 진입 직후부터 리스크를 적용한다.** 시가 진입 이후 봉 범위에 접촉할 수
있다고 가정한다. 슬리피지로 진입 직후 원시 시가가 기준을 벗어나면 시가 청산을 시도한다.
그 외 다중 접촉은 위 규칙을 따른다. 진입 봉 고저도 그 봉 트레일링에 사용하지 않는다.
청산 후 같은 봉에서 재진입하지 않는다. 청산한 봉 종가의 별도 신호는 다음 봉부터
진입할 수 있다. 마지막 봉도 열린 포지션의 리스크는 평가하되 다음 봉이 필요한 신규
신호 주문은 체결하지 않는다.

## 비용과 유동성 부족 정책

- 매수 = 원시 가격 × (1 + 슬리피지), 매도 = 원시 가격 × (1 − 슬리피지).
  LONG 청산은 매도, SHORT 청산은 환매이므로 항상 불리한 비용 방향이다.
- 청산 수수료 = 수량 × 청산 체결가 × 편도 수수료율. 진입 수수료도 별도로 반영한다.
- 봉별 총 체결 물량 한도는 **직전 관측 확정 봉 volume × 참여율**이다. 체결 봉 전체
  거래량은 미리 보지 않는다. 같은 봉의 진입과 리스크 청산은 한도를 공유한다.
  진입 수량은 자금·거래량 한도 중 작은 값으로 제한한다.
- **부분 청산은 구현하지 않는다.** 전량에 필요한 물량이 남은 한도를 초과하면 수량 0의
  거절 이벤트를 남기고 포지션 전체를 유지한다. 최초 리스크 사유·기준가·발생 봉을 고정한 뒤
  다음 관측 봉 시가마다 새 한도로 전량 청산을 재시도한다. 가격이 회복돼도 취소하지 않는다.
  실제 재시도 가격은 원래 기준가가 아닌 재시도 시가이며 손절률보다 손실이 커질 수 있다.
  끝까지 미체결이면 OPEN 상태로 최종 종가 평가한다.
- 거래량은 호가 유동성의 대용값이다. 현재 봉 실제 거래량이 0이어도 이전 봉 한도상 가상
  체결될 수 있다. 실제 체결 가능성을 보장하지 않는다.
- 누락 봉 안의 접촉은 알 수 없다. 신호는 연속성 검사로 체결을 거절하고, 보유 포지션의
  리스크/미체결 재시도는 다음 관측 봉 시가부터 평가한다.

STEP 5 공통 원장을 사용한다. `equity = cash + signed_quantity × close` 및
`equity = initial_capital + realized_pnl + unrealized_pnl`을 매 봉 검증한다.
실현 손익은 종료 거래 가격 손익에서 지급한 모든 수수료(미청산 진입비 포함)를 뺀다.
SHORT는 진입 시 1배 노출이며 매도 대금과 초기 노출 예산을 잠근다. 자동 리밸런싱은 없다.
갭 등으로 현금/자산이 음수가 되는 경로는 기존처럼 오류로 중단하며 손실을 0으로 잘라
성공한 결과를 만들지 않는다. 거래소 강제 청산 모형은 없다.

## 거래 로그와 UI

거래 원장 `exit_reason`: `SIGNAL_EXIT`, `STOP_LOSS`, `TAKE_PROFIT`, `TRAILING_STOP`.
기존 이벤트의 `reason=OPPOSITE_SIGNAL/OPPOSITE_SIGNAL_WITH_CONFLICT`는 호환성을 위해
유지하고 `exit_reason=SIGNAL_EXIT`를 추가한다. 거절 이벤트는 `reason`에 거절 원인,
`exit_reason`에 청산 의도를 기록한다. `requested_quantity`, `liquidity_available`는
거절 당시 수량·남은 한도다.

| execution_timing / exit_timing | 의미 |
| --- | --- |
| NEXT_OPEN | 신호 다음 봉 시가 |
| OPEN_GAP | 기준을 넘은 시가(진입 직후 시가 청산 포함) |
| INTRABAR_OHLC | 정확한 체결 시각을 알 수 없는 봉 내부 기준가 체결 |
| RETRY_OPEN | 리스크 미체결을 재시도한 관측 봉 시가 |

봉 내부 체결의 `execution_timestamp`와 `exit_timestamp`는 **NaT**다. 대신
`execution_candle_timestamp`/`exit_candle_timestamp`에 해당 봉 시작을 기록한다.
리스크 마커는 이 봉 위치를 가리키며 실제 봉 내부 체결 시각을 뜻하지 않는다.
리스크 이벤트에 전략 신호를 지어내지 않고 `signal_timestamp`를 NaT로 남긴다.
`trigger_candle_timestamp`, `risk_trigger_bar`는 재시도 후에도 최초 접촉 봉을 가리킨다.

전략 신호는 삼각형, 신호 진입/청산은 다이아몬드/원, 리스크 청산은 색상별 X로 표시한다.
비교 실행은 두 자산 곡선과 6개 지표를 표시한다. 상세 카드·가격 체결 마커는 Risk ON,
별도 expander는 Risk OFF 원장이다. 활성 리스크·전략·시장·데이터 변경은 결과를 무효화하고
단순 지표 표시 변경과 비활성 비율 변경은 결과를 바꾸지 않는다.

## 검증 및 실행

`tests/fixtures/step5_risk_off.json`은 STEP 6 변경 **이전** 엔진에서 생성한 10개
고정 합성 입력의 기준 결과다. `tests/test_risk.py`는 OFF의 모든 기존 자산 곡선·거래·
이벤트 컬럼 및 성과 수치를 비교한다(새 메타데이터 컬럼 제외). LONG/SHORT, 비용,
충돌, 거래량 부족, 미청산, 무거래, 빈 데이터, 반전을 포함한다. 손검산 리스크 테스트,
Streamlit AppTest, 선택적 실제 API 검증은 별도로 유지한다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
# 네트워크가 허용된 환경에서 실제 API 검증
$env:RUN_BINANCE_LIVE_TESTS='1'
.\.venv\Scripts\python.exe -m pytest -q tests/test_risk_live.py
Remove-Item Env:RUN_BINANCE_LIVE_TESTS
```

OHLC만으로 실제 경로·체결 지연·호가를 복원할 수 없다. 비용과 유동성 한도는 가정이고
SHORT는 실제 Binance Spot 거래가 아니다. 펀딩, 차입 비용, 증거금, 강제 청산,
최소 주문 단위는 제외한다. MDD는 초기 자산과 **봉 마감 자산** 기준이며 봉 내부 최저
자산을 재현하지 않는다. 리스크 적용이 수익률/MDD 개선을 보장하지 않는다. 과거 성과는
미래 성과를 보장하지 않으며 같은 데이터로 전략 개발·평가 시 과최적화 위험이 있다.
