## 사전 준비

- [ ] Windows/Python 3.11, `requirements-lock.txt` 설치 및 `pip check`, [README](../README.md)의 명령/사용 가능한 포트를 확인한다.
- [ ] 사용자 DB를 시연 중 변경하지 않으려면 **별도 오프라인 시연 프로세스**를 사용한다. 실 데이터 시연은 별도 프로젝트 사본/시험 DB를 준비하고 원본 `.env`/DB를 복사·게시하지 않는다.
- [ ] 일반 앱은 `app.py:8532`, 합성은 `demo/offline.py:8533` 같은 서로 다른 프로세스/포트를 사용한다. 이미 쓰는 서버는 종료하지 않는다.
- [ ] 브라우저 확대율/화면 공간을 확인하고 각 화면의 접기 메뉴를 미리 찾는다. 전면 UI 리디자인은 하지 않는다.
- [ ] 실 데이터 조회가 허용/가능한지, 마지막 확정 봉/수집 시각/실제 수집 범위를 확인한다. 실패하면 ‘실 API 성공’이라고 설명하지 않는다.
- [ ] 비교 전략 2개, 손절 1%, 실험 JSON/Markdown 다운로드 위치를 준비한다. 같은 이름만 바꾼 동일 조건 전략은 성과 차이를 보장하지 않는다.
- [ ] 저장 보고서·원장 JSON에는 개인 연구 내용이 있을 수 있다. 발표용 시험 결과만 사용하고 `.env`·키·인증 헤더·사용자 원본 DB는 화면에 열지 않는다.

## 네트워크 장애 시 안전한 전환

```powershell
.\.venv\Scripts\python.exe -m streamlit run demo/offline.py --server.address 127.0.0.1 --server.port 8533 --browser.gatherUsageStats false
```

처음부터 오프라인 합성 경로를 사용할 수도 있다. 일반 앱이 API 실패를 감지했다고 자동으로 가짜 가격을 넣지 않는다. 발표자가 별도 주소로 이동하고 **“지금부터 모든 시세/거시 수치는 합성 자료이며 실제 시장 분석이 아닙니다”**라고 밝힌다.

- ‘정상 흐름’은 최대 360개 확정 시각의 합성 봉이다. 시간프레임별 간격과 수집 범위 제한을 표시한다. 장기간 조회를 요청해도 실제 과거 전체가 있다는 뜻은 아니다.
- ‘자료 부족’은 2봉만 제공한다. RSI/ATR 등 초기 NaN과 UNKNOWN/INSUFFICIENT_DATA를 유지한다. 반올림 숫자나 LOW 등급을 임의로 채우지 않는다.
- ‘연결 실패’는 수집 오류만 주입하고 실제 외부 요청은 하지 않는다. DATA ERROR와 기존 원장 보존을 설명한다. 정상 흐름으로 돌아오면 명시적으로 재실행한다.
- 외부 요청과 OpenAI 클라이언트는 시연 프로세스에서 차단한다. 내부 자료의 FRED URL/단위는 형식 설명이며 실제 FRED 조회 성공의 근거가 아니다. 실제 발표일/빈티지는 생성하지 않는다.
- 시연 DB는 `.pytest_cache/sigfin-demo/<세션 ID>/demo.sqlite3`다. 새 세션은 새 DB이므로 사용자 영구 계좌와 혼동하지 않는다. 같은 세션의 저장/과거 조회를 시연하고 필요한 원장·리포트를 다운로드한다. 서버 재시작 후 영구 복원은 일반 앱의 별도 시험 DB/기존 자동 시험 근거로 설명한다.
- 합성 봉의 기준 시각은 세션 시작에 고정된다. 긴 시간 방치 후 가격 신선도 검증이 실패하면 검사를 우회하지 말고 새 세션으로 시작한다.

## 전달할 결과와 이월 사항

발표용 실험 JSON은 고정 OHLCV/전략/비용/Risk/코드 해시·결과 기준을 포함한다. 리포트 JSON/Markdown과 원장 내보내기는 서로 다른 산출물이다. 복원한 과거 보고서를 현재 조건의 새 분석으로 소개하지 않는다.

자동 검증 결과와 실제 브라우저 관측, 사용자의 과거 STEP 18 수동 확인을 구분한다. 발표 전체 10~15분 리허설·교수님 요구 제출 형식·장비/네트워크 점검은 사용자가 최종 확인해야 한다. 실계정 유료 LLM과 실제 Binance/FRED 통합 리포트 검수는 [BACKLOG](BACKLOG.md)에 남긴다.
