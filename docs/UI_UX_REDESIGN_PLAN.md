### 2.2 차트의 현재 기능

- 시장 차트는 Plotly Candlestick + 거래량의 공통 날짜축이다. EMA/SMA/Bollinger는 가격 위, RSI/MACD는 별도 하단 패널에 표시한다. RSI 30/70 기준선과 거래량 평균선도 이미 있다.
- RSI/MACD 선택 수에 따라 높이가 `560 + 170 × 패널 수`로 바뀐다. 상단 수평 범례에 여러 오버레이/신호/체결이 함께 들어간다.
- 조건 충족은 삼각형/충돌 표식, 가상 진입/청산은 별도 도형, 리스크 청산은 별도 표식이다. 봉 내부 리스크 청산은 정확한 시각 대신 해당 봉 위치와 체결 가정을 표시한다.
- `app.py`는 `theme=None`, `scrollZoom=True`, 반응형 Plotly 설정을 사용한다. Streamlit 테마만 바꿔도 차트의 하드코딩된 배경/폰트/색이 모두 바뀌는 구조는 아니다.
- 시장 차트의 `uirevision`은 종목/봉/기간·RSI/MACD 패널 선택에 연결돼 있다. 같은 화면 재실행의 확대 범위와 패널 변경 동작을 회귀 검증한다. 페이지를 떠났다가 돌아왔을 때의 확대 복원까지 자동 보장된다고 가정하지 않는다.
- 자산 곡선·거래별 손익·Risk 비교·전략 비교·거시/정규화 추이·산점도·시차 차트는 이미 각각 있다. 전략 비교는 전략별 색과 Risk OFF 점선/ON 실선을 구분한다.

## 4. 확정 정보 구조 — 좌측 6개 작업 화면

### 4.1 공통 틀

```text
좌측 메뉴                         상단·본문
SIGFIN · 시그핀                   현재 화면 이름 · 연구용/실제 주문 없음
시장 분석                         공통 현재 조회 조건: 종목·봉·기간
전략·백테스트                     자료 출처·조회 상태·확정 마감/수집 UTC
포트폴리오                       ───────────────────────────────────────
거시경제                         핵심 지표 카드 / 현재 작업 요약
AI 연구                          설정·명시적 실행 + 넓은 차트/결과
저장 이력                        근거/원장/고급 정보는 하위 탭·접기
```

- 첫 화면은 시장 분석으로 한다. 새 지표를 계산하는 별도 종합 홈을 만들지 않는다.
- 6개 메뉴는 네이티브 **좌측 내비게이션**으로 구성한다. 공통 종목·봉·조회 기간 위젯은 진입점의 상단 공통 영역에서 한 번 렌더링한다. 지표/전략/거시/AI 설정과 실행은 각 작업 화면에 두며 좌측 메뉴에 누적하지 않는다. 전역 설정을 위/왼쪽에 중복 생성하지 않는다.
- 화면이 좁으면 네이티브 내비게이션/세로 배치로 전환하고 다열 KPI·설정은 줄바꿈한다. CSS로 본문 전체를 강제 고정하거나 차트 밖 가로 스크롤을 유발하지 않는다.
- 공통 조건은 현재 조회용이다. 과거 보고서/업로드 실험은 자신의 고정 조건을 따로 표시한다. 이력 화면 방문만으로 시장/API를 재조회하지 않는다.
- ‘실제 공개 시장 자료/합성 자료’, ‘Mock/LLM 선택/실제 호출 여부’, ‘현재 결과/과거 저장 결과’는 서로 다른 상태다. 하나의 초록색 Live 배지로 합치지 않는다.

기존 기능의 위치를 옮기는 계획이다. 단일 AI SIGNAL은 단일 분석 결과라는 출처를 유지한 채 AI 연구 요약으로 옮긴다. 다른 Workflow의 방향 값을 대신 넣지 않는다. 시장에 ‘최근 AI 분석’을 재표시한다면 현재 입력과의 정합성과 과거/현재 표시가 먼저 필요하다.

### 4.3 전략 화면의 집중 배치

상단에 ‘편집 중 전략’과 현재 시장/비용/Risk 요약을 놓는다. 전략 편집에서는 LONG/SHORT·동일 AND/OR 그룹을 나란히 또는 화면 폭에 따라 위아래로 배치한다. JSON 저장/불러오기는 편집 도구 옆에 둔다.

하위 작업은 ‘전략 편집 / 단일 백테스트 / 전략 비교 / 저장 실험 재현’으로 나눈다. 공통 원금·편도 비용·참여율·활성 Risk 값을 **하나의 설정 원본**에서 읽는다. 비교 화면에서 손절 설정을 찾으러 다른 화면으로 이동하지 않도록 같은 화면의 공통 설정으로 돌아가는 조작을 제공한다. 같은 위젯을 두 번 만들어 서로 다른 값을 저장하지 않는다.

결과는 성과표 → 자산 곡선 → Risk ON−OFF 차이 → 거래/체결 원장 → 재현 정보다. 비교 설정이 모두 OFF면 기존 경고를 유지한다. 업로드 실험의 저장 설정을 현재 설정으로 바꾸지 않는다. 재실행 해시 상태는 표 근처에서 항상 확인할 수 있게 한다.

### 4.4 AI·보고서의 읽기 순서

1. 종목/봉·자료 시각·Mock/실제 호출 여부·현재/과거 결과.
2. 분석 의견과 별도 위험 등급/연구 상태. `BULLISH`와 `HIGH`, `ABSTAIN`은 동시에 표시될 수 있다.
3. 기술/Macro 요약·상승/하락·상충·주요 위험·자료 부족.
4. 검증된 근거 표, 에이전트 상태/소요 시간·Debate 기록.
5. 저장·Markdown/JSON 다운로드와 비용/오류 기록.
6. `원본 저장 데이터 보기 (개발자용)`은 기존대로 기본 닫힘. 내부 추론을 새로 생성/표시하지 않는다.

LLM 모드 선택만으로 실 API 결과라고 표시하지 않는다. 실제 호출 여부·PARTIAL/FAILED·Macro 미호출/자료 부족을 개별 노드에 보존한다. 비용 경고·승인은 실행 버튼 바로 위에 둔다.

## 5. 공통 디자인 시스템 — 1단계 설계 기준

### 5.1 디자인 원칙과 참고

중요한 결과를 먼저 읽고 조건/근거/상세로 내려가게 구성한다. 토스 공식 자료의 정보 위계·상위 구조부터 세부 상태를 정리하는 방식을 참고해 SIGFIN 컴포넌트 가이드도 같은 읽기 순서를 사용한다. 이는 해당 디자인 자산을 복제한다는 의미가 아니다. [토스 디자인 시스템 가이드](https://toss.tech/article/toss-design-system-guide)

TradingView의 작업 공간은 종목/주기/지표/스타일을 함께 다룬다. SIGFIN에는 이 개념을 참고해 차트와 조건 제어를 가깝게 배치하되 현재 Plotly로 제공하는 기능을 유지한다. 도형 도구·다중 동기화 차트·주문/브로커를 새로 넣지 않는다. [TradingView 레이아웃 안내](https://www.tradingview.com/support/solutions/43000746975-tradingview-layouts-a-quick-guide/)

### 5.2 확정 설계 토큰

| 범주 | 설계 기준 | 적용 원칙 |
| --- | --- | --- |
| 브랜드/주 동작 | 네이비 `#0F172A`, 블루 `#1D4ED8`, 선택 배경 `#EFF6FF` | 헤더/제목·선택·주 실행 버튼. 한 작업 영역에 주 동작 1개 |
| 배경 | 페이지 `#F5F7FB`, 카드 `#FFFFFF` | 약한 면 분리, 과도한 그림자/큰 공백 줄이기 |
| 텍스트/경계 | 본문 `#0F172A`, 보조 `#475569`, 경계 `#E2E8F0` | 보조 문구도 읽을 수 있게 하고 경계선만으로 의미 전달하지 않기 |
| 성공/손실/경고 | 텍스트 `#166534` / `#B91C1C` / `#92400E` | 배경색만으로 상태를 구분하지 않고 이름·부호·아이콘 병기 |
| 간격/크기 | 4/8/12/16/24/32px, 카드 반경 12px | 공통 간격/모서리, 불필요한 반복 카드 최소화 |
| 글자 | 본문 14~16px, 보조 12~13px, 절 제목 20~24px, 핵심 값 24~32px | 한국어 시스템 폰트 우선, 외부 폰트/CDN 요청 없이 시작 |
| 숫자 | 우측 정렬·가능한 범위의 고정 폭 숫자, 단위 옆 표시 | 보유 수량과 가격의 표시 정밀도 구분, 계산 값 반올림/손익 자체 변경 금지 |
| 레이아웃 | 좌측 메뉴 약 240~260px, 본문 최대 약 1440~1600px 목표, 좁은 폭에서 세로 전환 | 실제 장비/네이티브 레이아웃에서 최종 검수. 강제 가로 스크롤 방지 |

색/표시 규칙은 1단계 설계 기준이며 현재 UI에 적용하지 않았다. 크기는 반응형 목표로 구현한다. 일반 텍스트 4.5:1, 큰 텍스트 3:1을 접근성 검수 목표로 삼되 실제 전경/배경 조합을 측정하고 키보드/확대 검수도 별도로 한다. 설계 기준만으로 접근성 준수를 선언하지 않는다. [W3C 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

캔들 **상승 녹색·하락 빨간색**은 기존 의미를 유지한다. 한국어 UI라는 이유로 토스증권의 색상 규칙을 그대로 적용하지 않는다. 선/도형/텍스트를 함께 사용하고 EMA/SMA/MACD 등의 계열은 서로 구분되는 팔레트를 유지한다. Risk OFF 점선/ON 실선과 실제 체결/신호/리스크 청산의 도형 구분도 보존한다.

### 5.3 공통 요소·상태 문구

- 공통 헤더/조건 요약, 자료 품질 배지, 숫자 카드, 설정 요약, 실행 도구줄, 경고/빈 상태, 근거 표, 원장 표, 차트 스타일, 과거 결과 배너, 기본 닫힌 개발자 원본 메뉴를 우선 정리한다.
- ‘정보 없음’을 `0`으로 통일하지 않는다. 미조회/조회 실패/표본 부족/계산 N/A/실제 0/무거래를 구분한다.
- 화면에는 `BULLISH → 상승 관점`, `BEARISH → 하락 관점`, `NEUTRAL → 중립`, `INSUFFICIENT_DATA → 근거 부족`처럼 표시 사전을 둔다. 원본 enum·저장 필드는 유지한다.
- `REVIEW/HOLD/ABSTAIN`은 ‘검토/연구 보류/판단 유보’ 등으로 설명하고 실제 주문/보유 명령이 아니라는 안내를 유지한다.
- `%` 수익률/금리 수준, `%p` 금리 변화·성과 차이, USDT 가격/자산, BTC/ETH 수량, 고용 ‘천 명’, CPI 지수/MoM/YoY를 구분한다. 시각은 UTC와 봉 시작/마감·관측일/수집 시각을 명시한다.
- `Stop Loss/Take Profit/Trailing Stop`은 ‘손절/익절/트레일링 스톱’으로 표시하되 기존 설정 키/값은 바꾸지 않는다. 오류의 내부 유형은 상세에 보존한다.
- 중요 안내(유료 승인·자료 실패·부분 분석·실제 주문 아님)는 닫힌 메뉴로 숨기지 않는다. 긴 원본 JSON·실행 상세는 접되 결과를 중복 출력하지 않는다.

테마는 향후 `.streamlit/config.toml`의 네이티브 설정을 우선하고, UI 전용 토큰/컴포넌트에서 재사용한다. Plotly는 `theme=None` 및 자체 색상이 있으므로 별도의 표시 스타일 공통화를 계획한다. 계산/축 자료를 스타일 함수에서 수정하지 않는다. 새로운 CSS는 지원되는 테마로 해결되지 않는 부분에만 한정한다.

### 6.3 페이지 이동과 데이터 전달의 필수 조건

1. **공통 위젯:** `symbol/timeframe/period`는 진입점에서 렌더링한다. 페이지별 위젯은 설치 버전의 지원 범위에서 `persist_state="session"`을 검토하고, 동적 조건/파일 업로드 등은 별도 애플리케이션 상태 어댑터로 다룬다. 버튼 클릭/승인 이벤트를 저장된 실행 명령으로 복원하지 않는다.
2. **공식 수명 규칙:** 위젯은 페이지에 따라 identity가 달라질 수 있다. 같은 `key`를 옮기는 것만으로 유지가 보장되지 않는다. 공통 진입점 위젯·영속 위젯 옵션·별도 상태의 전략을 맞는 요소에 선택하고 이동/숨김/복귀 시험을 먼저 통과한다. [Streamlit 다중 페이지 위젯](https://docs.streamlit.io/develop/concepts/multipage-apps/widgets)
3. **단일 상태 원본:** UI 전용 상태 모듈에서 현재 전략/백테스트 설정/선택 Macro/계좌/평가 이력·Risk 설정을 기존 타입으로 제공한다. 다른 페이지를 먼저 열어야 설정이 준비되는 구조를 만들지 않는다. 원본 DataFrame은 불필요하게 복사/재계산하지 않는다.
4. **순서 의존 제거:** 통합 리포트는 현재 `current_research_context()`가 계좌/가격 이력·`_backtest_key`·`_portfolio_risk_signature` 등을 읽는다. 포트폴리오/백테스트 화면을 그리지 않아도 최신 유효 문맥을 얻도록 UI 조립 계층을 정리한다. 존재하는 DB의 읽기만 필요하다면 기존 API로 조회하되, 이력 조회가 DB 생성/저장을 일으키지 않게 한다.
5. **포트폴리오 가격:** `render_portfolio()`의 반환값은 `PortfolioPriceContext`이고 `render_portfolio_risk(*, price_context=...)`로 전달한다. 같은 이름의 세션 `_portfolio_price_context`는 현재 **봉/기간 튜플**이므로 반환 객체로 착각하지 않는다. 위험 계산에는 계좌 ID/revision·quotes/frames·동일 평가 UTC를 전달하고 재검증을 유지한다.
6. **활성 화면만 실행:** `st.navigation` + `st.Page`의 공통 틀에 기존 화면 어댑터를 연결하는 방안을 우선한다. 기존/신규 화면을 모두 렌더링하고 CSS로 하나를 숨기는 방식은 위젯 키/부수효과를 중복시킬 수 있다. 일반 `st.tabs`/접기 메뉴는 그 자체로 비활성 내용의 계산을 막지 않는다.
7. **호출 시점:** 페이지 이동·테마/지표 표시·이력/다운로드로 유료 호출·가상 거래·저장·실험 재실행이 발생하면 회귀다. 첫 시장 방문/수동 새로고침의 기존 수집 정책과 TTL은 유지하고, 재방문은 유효 캐시를 사용한다. TTL 만료 뒤 필요한 공개 자료 재조회는 캐시 정책에 따른 동작으로 별도 측정한다.

설치된 1.64.0의 `st.navigation(position="sidebar")`, `st.Page(callable)`, 선택 위젯의 `persist_state`, 다운로드의 `on_click="ignore"` 지원을 기준으로 계획한다. 실제 적용은 2단계 탐색/상태 검증 지점에서 시험한다. 파일 기반 페이지가 필요하면 `app_pages/`를 사용하고 기존 자동 검색용 `pages/`와 혼용하지 않는다. 새 옵션을 적용하려고 의존성을 임의 업그레이드하지 않는다.

### 6.4 무효화 규칙은 하나로 합치지 않는다

- **백테스트:** `result_fingerprint()`의 전략/비용/Risk·자료 값/인덱스/컬럼·버전 기준을 유지한다.
- **Workflow:** `input_signature()`는 기본적으로 수집 시각까지 구분한다.
- **통합 리포트:** `include_collection_time=False`로 같은 관측의 유효한 수집 시각 갱신만으로 저장 전 결과가 사라지지 않게 한 기존 수정이 있다. 실제 값/전략/모드/원장/가정/메모 변경은 무효화한다.
- **STEP 18:** `current_input_key()`는 유효한 수집 시각을 검증한 뒤 단순 재수집 시각은 제외한다. 저장 기준 해시를 현재 결과에 맞춰 다시 쓰지 않는다.
- **보유 위험:** 가격·계좌 revision·가정·평가 이력 정합성을 확인한다. 시세가 화면에 숫자로 보인다는 이유로 통과시키지 않는다.

새 페이지에서 결과를 다시 보여줄 때도 해당 검사를 수행한다. 화면 위치/선택 메뉴/테마 같은 UI 정보는 기존 계산 지문에 섞지 않는다. 반대로 실제 변경 검사를 생략해 오래된 결과를 현재 결과처럼 표시하지 않는다.

### 6.5 SQLite·저장·다운로드 계약

- 계좌 생성/가상 거래는 명시적 버튼/폼과 검증을 거치고, DB 저장 성공 후에만 세션 상태/nonce를 갱신한다. 페이지 표시/AI 결과/시세 갱신으로 거래를 만들지 않는다.
- 원장 JSON 복원은 명시적인 검증/불러오기 동작이다. 과거 분석 조회가 현재 원장을 덮어쓰지 않는다. 과거 보고서는 저장 당시 입력/시각/모드로 표시하고 새 API 호출로 재작성하지 않는다.
- 저장소 v1·ID·revision·SHA·스냅샷 스키마/컬럼/정밀도·안전한 JSON 직렬화·파일명/mime·검증 제한은 유지한다. 한국어 표시를 위해 원본 저장 키/지표명을 번역하지 않는다.
- 다운로드 버튼 위치/스타일은 바꿀 수 있으나 자료 내용/기준 해시·동일 실행의 Markdown/JSON 정합성과 SQLite 저장·복원을 유지한다. 표시용 표의 열 이름 변경은 사본/column configuration에 한정한다.
- 파일 업로더는 페이지를 떠나며 위젯 상태가 사라질 수 있다. 실험 입력은 검증된 크기 한도 내 원본 바이트/해시와 파싱 결과의 명시적 관계를 보존하고, 새 파일/제거는 이전 비교를 무효화한다. 임의 경로에 파일을 저장하거나 과거 업로드를 자동 재실행하지 않는다.
- 다운로드 rerun을 줄이는 옵션은 표시 단계에서 검토할 수 있지만 기존 저장 무효화 안전장치를 대신하지 않는다. 같은 확정 봉 재수집 → 저장 → 다운로드 → 과거 조회 회귀를 반드시 수행한다.
- 테스트는 임시 DB와 복사본/표준 backup만 사용한다. 사용자 원본 DB를 시험 도중 쓰거나 스키마를 바꾸지 않는다. 원본 DB의 실제 백업/교체는 별도 사용자 작업이며 [운영 안내](local_operation.md)를 따른다.

### 6.6 API·Mock·오프라인 시연

실제 키의 위치/읽기·로그 비노출, 유료 요청 버튼/경로별 승인·기본 세션 5회/$0.25·지원 가격 만료·동시 예약·중복/재시도 정책을 그대로 사용한다. 단일/Workflow/통합의 모드를 하나의 전역 Live 스위치로 합쳐 비용 승인을 전파하지 않는다.

[demo/offline.py](../demo/offline.py)는 별도 프로세스의 합성 시연이다. 새로운 앱 틀에서도 주입 범위 안에서 선택 화면이 실행돼야 하며 세션 UUID DB·공유 잠금·HTTP/OpenAI 차단이 유지돼야 한다. 일반 앱과 합성 시연은 둘 다 테스트한다. 합성 배너는 페이지를 이동해도 사라지지 않게 하고 실제 시장 실패를 자동 합성으로 바꾸지 않는다.

## 8. 검증 계획과 사용자 확인표

### 8.1 자동 시험 기준

- 기준 646개는 과거 성공 수다. 구현 후 실제 통과/실패/skip·하위 시험 수를 새로 기록한다. 원래 opt-in 외부 14개는 실행하지 않았다면 미검증으로 유지한다.
- 기존 `tests/test_*_ui.py`가 단일 페이지 배치/사이드바 체크 수를 검사하는 부분은 새 화면 접근 시험으로 이관한다. 위치/표시 문구 검사는 바꿀 수 있지만 기능·호출 수·보존·오류 검증을 제거하지 않는다. 금융/저장/그래프 순수 시험은 그대로 유지한다.
- 같은 fixture의 순수 엔진 결과·현금/수량/수수료/실현/미실현·시각·증거 ID·실험 input/code/result SHA는 동일해야 한다. 화면 스타일의 차이는 허용하지만 원본 DataFrame/보고서 스냅샷은 변경되면 안 된다.
- Plotly 전체 JSON은 스타일 변경으로 달라질 수 있으므로 수치 배열·시각·지표 선택·마커 분류/시점·축 단위/NaN 연결 방지 등을 별도로 검증한다. 표시 스타일만 바뀌었다고 데이터 검사를 생략하지 않는다.
- 전체 경로 통합에는 ‘편집 → 화면 이동 → Risk ON 실행 → 실험 저장/재현 → 계좌/위험 → Mock 보고서 저장/과거 조회 → 다운로드’를 포함한다. API 호출 횟수·가상 이벤트/DB revision·공유 예산이 예상대로인지 함께 검사한다.
- 업로더/네이티브 다운로드/Plotly 조작·포커스·실제 expander 닫힘은 AppTest만으로 충분하다고 하지 않는다. 격리 Edge/시험 DB에서 보완한다.

향후 공통 명령:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest -q --tb=short -ra
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --server.port 8532 --browser.gatherUsageStats false
# 별도 프로세스·빈 포트에서 합성 시연
.\.venv\Scripts\python.exe -m streamlit run demo/offline.py --server.address 127.0.0.1 --server.port 8533 --browser.gatherUsageStats false
```

이 명령을 이번 계획 작업에서 실행하지 않았다. 구현 시에도 사용 중인 서버를 종료하지 말고 빈 포트를 사용한다. 유료 요청 승인을 시험하려고 실제 과금을 발생시키지 않고 모의 응답을 사용한다.

### 8.2 수동 수용 체크리스트 — 모두 향후 검증

- [ ] 1366×768/1440×900/1920×1080에서 핵심 값/차트/버튼을 읽고 접근할 수 있다. 768px·390px 폭에서도 필수 안내/폼이 잘리거나 페이지 전체가 강제 확대되지 않는다.
- [ ] 100%/125%/200% 확대, 키보드 Tab/Shift+Tab/Enter, 포커스와 입력 라벨·색 이외의 상태 단서를 확인한다. 실제 대비를 측정한다.
- [ ] 종목/봉/기간·지표 변경 후 메뉴 왕복 시 전략 초안·비용/Risk·미저장 메모가 의도대로 유지되고 오래된 결과는 현재 것으로 보이지 않는다.
- [ ] 가격 오류/2봉 부족/부분 자료에서 차트/지표/계좌/AI가 N/A·UNKNOWN·INSUFFICIENT_DATA를 정직하게 표시한다. 이를 0/LOW/완료로 대체하지 않는다.
- [ ] 신호와 next-open 체결/봉 내부 위험 마커·UTC/단위가 구분된다. 손절 1%가 발동하는 fixture에서 ON/OFF 및 STOP_LOSS 원장이 구분된다.
- [ ] 2전략×Risk×3구간 12회, 실험 JSON 다운로드/업로드/재실행·MATCH, 변조·기준 없는 파일의 MISMATCH/UNAVAILABLE, 8MB 초과 안내를 확인한다.
- [ ] 시험 계좌 매수/일부 매도·확인 폼·중복 클릭·계좌 복귀/가격 재검증·-10% 충격과 현금·손익을 대조한다. 새 계좌/복원 조작을 오인해 기존 계좌를 바꾸지 않도록 설명한다.
- [ ] 같은 확정 값의 캐시 재수집 뒤 통합 리포트 저장/다운로드가 유지된다. 실제 전략/값/모드/원장 변경은 무효화된다.
- [ ] 과거 요약을 읽을 때 긴 JSON이 기본 노출되지 않는다. 개발자 메뉴 열기/닫기·재조회 초기화, Markdown/JSON HTTP 다운로드·임시 DB 재시작 복원을 확인한다.
- [ ] Mock 기본·서로 다른 세 분석 경로·노드 실패/PARTIAL·공유 예산이 명확하다. 메뉴 이동/초기 로딩/다운로드로 유료 호출/거래/저장을 만들지 않는다.
- [ ] 합성 시연 배너/시험 DB/통신 차단이 모든 새 화면에서도 유지된다. 사용자 브라우저/원본 DB 대신 격리 프로필을 사용한다.
- [ ] 최종 리디자인 수용 결과를 화면별로 기록한다. 이번 계획이나 과거 사용자의 오프라인 정상 보고를 새 디자인의 수동 통과로 소급하지 않는다.

## 9. 진행·기록 관리

최초 계획과 후속 R01 기록은 보존한다. 현재 진행 단위는 **1단계 설계·2단계 전체 구현 완료, 3단계 최종 검증 미착수**다. 활성 [BACKLOG](BACKLOG.md)에는 SF-POST-01의 남은 3단계만 연결하고, 완료한 구현과 자동/제한된 브라우저 결과는 CHANGELOG/[구현 기록](redesign/IMPLEMENTATION_STAGE_2.md)에 남긴다. R01 보호 문서의 이전 단계 식별자는 7절 대응표에 따라 적용한다.

향후 각 단계에서는 실제 수정 파일·시험 명령/결과·사용자 확인·발견 오류와 해결·이월을 기록하고 완료된 일만 활성 백로그에서 제거한다. 실제 UI가 바뀐 시점에 CHANGELOG/사용 안내를 갱신한다. 이번 계획 작성만으로 기존 STEP 1~20 개발일지나 CHANGELOG에 UI가 적용됐다고 기록하지 않는다.

Git 커밋/Push·원본 DB/키 변경·유료 API 호출·실제 주문은 이 계획으로 승인되지 않는다. 외부 API 검수/발표 리허설과 리디자인 수용 결과를 각각 구분한다.
